# Roadmap

## Purpose
Define the expected development path for the BAS programming assistant.

## Scope
This roadmap is directional. It should guide sequencing but does not replace issue tracking.

## Inputs
- Project goals.
- Technical dependencies.
- User feedback.
- Validation results.

## Outputs
- Development phases.
- Priority guidance.
- Future capability list.

## Dependencies
- [Vision](VISION.md)
- [Architecture](ARCHITECTURE.md)
- [Decision Log](DECISIONS.md)

## Design Reasoning
The project should build trust before breadth. Foundational schemas, validation, and deterministic generation come before advanced AI workflows.

## Phases
- Phase 1: Wiki, conventions, and domain model drafts.
- Phase 2: Structured project import and validation.
- Phase 3: Point, equipment, and controller models.
- Phase 4: Deterministic checkout and report generation.
- Phase 5: Graphics and logic generation.
- Phase 6: AI-assisted review, explanation, and troubleshooting.
- Phase 7: Vendor-specific integrations.

## Future Improvements
- Add milestones with owners and dates.
- Add risk register.
- Add acceptance criteria for each phase.

## Examples
- Do not build Niagara export before the internal logic model is stable.
- Do not add AI troubleshooting before trend and alarm data models exist.
